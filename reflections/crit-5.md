Crit 5 Reflection
What was the breakthrough that moved the work forward?
The biggest breakthrough came from playing the whole game myself. I did not only rely on the test results. The first version passed all its tests, but it used normal arithmetic precedence. This was different from the step-by-step calculation I wanted.
I changed the rule to calculate strictly from left to right. I also displayed the result after every step. This made the game more direct and easier to understand. Players no longer needed to plan the whole expression in their heads before clicking.
While testing all the levels, I found a fraction in Level 17. This showed me that a mathematically correct answer may still create the wrong game experience. I added a rule that every step must produce an integer. I also reduced the game from 30 levels to 21. This made it more realistic to finish within five minutes and matched the Make 21 theme better.
What did this work change about who I want to be as a software developer?
This project taught me that passing tests only shows that the program follows the written rules. It does not prove that the rules are good.
AI can help me write code, generate levels and create tests quickly. However, I still need to decide whether the game is clear and interesting. I need to use the finished product myself and look at it from the player’s perspective.
I want to be a developer who does not stop thinking when the code works. I want to find problems through real use and explain clearly what should change and why. I also learned that removing unnecessary content can be better than adding more features. A smaller and more complete game can create a better experience.
