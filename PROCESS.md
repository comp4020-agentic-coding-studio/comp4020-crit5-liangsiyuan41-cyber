Process
I decided to make a small arithmetic puzzle called Make 21. The player receives four number tiles and must use each one exactly once with addition, subtraction, multiplication or division to reach 21. A wrong answer ends the attempt, while a correct answer unlocks the next level.
I first asked Claude to separate the calculation rules from the interface so they could be tested independently. The first commit created exact arithmetic and expression validation ([bf406c1](https://github.com/comp4020-agentic-coding-studio/comp4020-crit5-liangsiyuan41-cyber/commit/bf406c1)). I then added a level bank and a solver to verify that every puzzle had an answer ([4ca8bfc](https://github.com/comp4020-agentic-coding-studio/comp4020-crit5-liangsiyuan41-cyber/commit/4ca8bfc)). After that, I built the playable interface with level unlocking, Undo, Reset, View Answer and Submit ([e3b533d](https://github.com/comp4020-agentic-coding-studio/comp4020-crit5-liangsiyuan41-cyber/commit/e3b533d)).
When I played the game, I found that the original calculation rule was not very clear. Because there were no brackets, the player had to plan the complete order of operations in advance. I decided that each operation should instead calculate immediately from left to right. For example, 9 − 1 first becomes 8, and the next step can use that result. This made the game easier to understand, more direct and more interesting.
I then played all 30 levels. In Level 17, I found the result 7/2, which was completely different from what I expected because I wanted the game to use integers only. I asked Claude to prevent fractional results. I also felt that 30 levels would be difficult to finish within five minutes, while 21 levels matched the game’s name and goal. Instead of simply deleting the last nine, I asked Claude to select from all 30 levels and reorder them from easy to difficult. The final version passed all 40 tests ([74fff12](https://github.com/comp4020-agentic-coding-studio/comp4020-crit5-liangsiyuan41-cyber/commit/74fff12)).
